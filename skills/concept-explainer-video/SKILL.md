# 概念解释短片 · 动画与剪辑规范

这份文档解决一件事：把一个抽象概念，做成 90 秒左右、像素风动画、看完就懂的短片。

风格不是凭感觉定的，锚在四个参考上。以后每做一支片子，都跟这四个对齐，风格才能固定下来。

---

## 一、四个风格锚点（先记住各自负责什么）

| 参考 | UP | 时长 | 在本 skill 里负责 |
|---|---|---|---|
| [大白话半小时理解网络](https://www.bilibili.com/video/BV1tseyzCEoF) | 飞天闪客 | 29:24 | **动画演绎方式**：怎么把抽象机制画成能动的东西 |
| [金融世界观-基础分析框架](https://www.bilibili.com/video/BV1Z4RHYKEcB) | 阿周的Eureka | 5:41 | **像素风视觉 + 引入动画**：整片美术基调、开场怎么起 |
| [库克时代](https://www.bilibili.com/video/BV1G7tG6tEwL) | 何同学 | 44:35 | **剪辑节奏 + 配乐 + 口播语气** |
| [Git+GitHub核心概念大串讲](https://www.bilibili.com/video/BV1ySLc6QEcB) | 技术爬爬虾 | 43:50 | **成品标杆**：引言段 00:00–01:50 就是要复刻的效果 |

### 为什么是这四个

- 飞天闪客解决"看不见的东西怎么演"。网络协议这种纯抽象的机制，他能画成有实体、会动、能追着看的过程。我们的概念也一样抽象，抄他的思路。
- 阿周的 Eureka 解决"整片长什么样"。B站 tag 里明确标着「像素风」，这是我们定下来的美术方向。5 分 41 秒讲完一个分析框架，密度也是我们要的。
- 何同学解决"怎么剪、配什么、怎么说"。他的《库克时代》分 10 章，序章一个人占 5 分钟，后面 9 章平均 4 分 27 秒——序章舍得给时间，正文压得紧。这个节奏观直接搬。
- 技术爬爬虾的引言段是硬指标：**110 秒讲清 Git 和 GitHub 是什么**。我们的成品就照这个量级。

### 三条不能破的底线

1. **美术只有一种：像素风。** 不许某支片子突然改成扁平插画或 3D 写实。风格固定的前提是不换风格。
2. **每一帧都要在解释概念。** 不服务于理解的炫技动效一律删。飞天闪客的动画好看是结果，不是目的。
3. **时长 75–110 秒。** 低于 75 秒讲不透，高于 110 秒就不是"一分半"了。以 110 秒为硬上限，对标 Git 那支的引言段。

## 二、90 秒结构模板（照这个搭，五段）

总时长 90 秒（可在 75–110 秒间浮动），五段的占比是固定的：

| 段 | 名称 | 时长 | 占比 | 任务 |
|---|---|---|---|---|
| 1 | 钩子 | 0–8s | 9% | 抛出一个让人想知道答案的问题 |
| 2 | 引入动画 | 8–20s | 13% | 像素风开场，标题落定 |
| 3 | 核心演绎 | 20–65s | 50% | 用动画把概念演一遍，全片主体 |
| 4 | 收束 | 65–82s | 19% | 一句话定义 + 一个记得住的类比 |
| 5 | 片尾 | 82–90s | 9% | 落标识，留 2 秒静场 |

### 各段具体要求

**第 1 段：钩子（0–8s）**

不许用「今天我们来讲一讲」这类开场。要抛一个真实的困惑：

```
✅ 「你提交的代码，到底存在哪？」
✅ 「为什么两个人改同一个文件不会打架？」
❌ 「今天我们来了解一下 Git 是什么。」
❌ 「大家好，欢迎收看本期视频。」
```

画面上给一个具体的、能看懂的场景，不要空镜配字。

**第 2 段：引入动画（8–20s）**

这段照阿周的 Eureka 的开场做。要素：

- 像素网格从画面某一侧生成或推入
- 标题以像素字体逐块拼出，不是淡入
- 有一个明确的"落定"动作（标题卡定住 0.5–1 秒）再进正文
- 全段 12 秒，不要拖到 15 秒以上

**第 3 段：核心演绎（20–65s）**

全片的价值都在这 45 秒。方法照飞天闪客：**给抽象概念一个实体，然后让实体动起来。**

| 抽象概念 | 给它什么实体 |
|---|---|
| 数据包在网络里传输 | 一个带地址标签的小方块，在管道里跑 |
| Git 提交 | 一个存档点，像游戏存档一样盖章落下 |
| 分支 | 铁轨岔道，小车驶入不同轨道 |
| 借贷关系 | 两个像素小人之间递过去的一枚硬币 |

演绎的三条要求：

1. **一次只动一个东西。** 同时有两处以上在动，观众不知道该看哪。
2. **每个动作后停 0.3–0.5 秒。** 给理解留缝，不要连续动作糊在一起。
3. **拆成 3–5 个小步骤。** 45 秒装不下更多。装不下就说明概念选大了，拆成两支片子。

**第 4 段：收束（65–82s）**

两句话，顺序不能颠倒：

```
1. 一句话定义：「Git 是管你代码历史的，GitHub 是放代码的地方。」
2. 一个类比：「Git 是相机，GitHub 是相册。」
```

类比放在定义后面。先给准确的，再给好记的。

**第 5 段：片尾（82–90s）**

- 落标识 / 账号名
- **最后 2 秒必须是静场**：画面定住，BGM 收干净，不要卡在音乐中间切黑
- 不加"求点赞求关注"的口播

## 三、动效脚本（每支片子必须先写这个）

动效脚本是施工图。**不写完不许开工。** 表格模板在 `templates/动效脚本模板.md`。

### 列定义（9 列，一列都不能少）

| 列 | 填什么 | 示例 |
|---|---|---|
| 镜号 | S01、S02… | S03 |
| 时间码 | 起–止，精确到 0.1 秒 | 20.0–24.5 |
| 时长 | 秒 | 4.5s |
| 画面内容 | 这一镜画面上有什么 | 像素小人站在左侧，右侧空白 |
| 元素入场 | 位移/缩放/描边生长/遮罩擦除/像素消散 | 遮罩擦除，从左到右 |
| 缓动曲线 | ease-out / ease-in-out / 弹性 / 线性 | ease-out |
| 字幕文案 | 屏幕上的字，一字不差 | 代码先存在你自己电脑上 |
| 配音/音效 | 旁白原文 + 音效点 | 旁白同字幕；落地音效 |
| 备注 | 素材来源、待补项 | 小人素材待生成 |

**「元素入场」和「缓动曲线」这两列是 MG 动画和普通剪辑的分界线。** MG 的活全在元素怎么动上，这两列空着等于没写脚本。

### 五种入场方式（只用这五种，固定下来）

```
位移      元素从画面外滑入          用于：新角色、新对象出场
缩放      从 0 弹到 100%            用于：强调、结论落定
描边生长  线条自己画出来            用于：连接关系、流程箭头
遮罩擦除  像被擦子擦出来一样显现    用于：文字、区块
像素消散  拆成像素点飞散/聚合       用于：转场、状态改变
```

不要自创第六种。风格固定靠的就是词汇表有限。

### 缓动曲线怎么选

| 场景 | 曲线 |
|---|---|
| 元素入场 | ease-out（快进慢停，有分量） |
| 元素退场 | ease-in |
| 位置移动 | ease-in-out |
| 强调、弹出 | 弹性（回弹一次，不要弹三次） |
| 匀速运动（数据包跑管道） | 线性 |

默认用 ease-out。拿不定就 ease-out。

## 四、像素风美术规范

### 技术参数

| 项 | 值 |
|---|---|
| 分辨率 | 1920×1080（横版主用）/ 1080×1920（竖版分发） |
| 帧率 | 25 fps |
| 像素网格 | 基准 4px 或 8px，全片统一，不许混用 |
| 缩放方式 | 最邻近（nearest neighbor），**绝对不能用双线性** |
| 输出格式 | H.264 mp4 |

**最邻近插值这条最容易翻车。** 像素素材一旦被双线性缩放就会发虚，像素风立刻变成"低清图片"。AE 里要把图层的品质设成「草稿」或用 nearest 采样，Pr 里要关掉缩放平滑。

### 配色

一支片子的主色板控制在 **5–7 色**，包含：

```
底色      1 色（深色打底，像素风别用纯白背景）
主体色    2–3 色
强调色    1 色（只给重点用，出现次数越少越有力）
文字色    1–2 色
```

**配色一旦定下，后续所有片子都用同一套。** 这是"固定风格"最直接的体现——观众看到颜色就知道是你的片子。

新建 `templates/配色方案.md` 记录实际色值，每支片子都从这里取色。

### 字体

- 标题：像素字体（如 Zpix 最像素、Fusion Pixel 缝合像素体，都是开源可商用）
- 字幕：思源黑体 或 站酷字体（**必须确认商用授权**）
- 全片字体不超过 2 种

⚠️ 字体和 BGM 的商用授权是校园号最容易踩的雷。校园账号也算公开传播，用了没授权的字体会被追。

## 五、AI 生图与生视频

### 分工原则

| 工作 | 用什么 |
|---|---|
| 静态像素素材（角色、图标、场景元素） | AI 生图 |
| 元素的运动 | **手做动画（AE / 剪映关键帧）** |
| 需要真实质感的插入镜头 | AI 生视频 |
| 建模类演示 | 3D 软件或 AI 生视频，但要后处理成像素风 |

**核心：运动交给自己做，不要交给 AI 生视频。** AI 生视频现在控不住"元素按你想的方式入场"，而入场方式恰恰是我们风格的核心。AI 生图出素材、自己排关键帧，这个分工最稳。

### 生图提示词模板

```
pixel art, [主体描述], [动作/姿态], limited palette of [颜色1] [颜色2] [颜色3],
[4px/8px] pixel grid, flat shading, no anti-aliasing, no gradient,
transparent background, side view, game sprite style
```

四个必须写进去的负向约束：

```
no anti-aliasing     防止边缘发虚
no gradient          像素风不用渐变
no outline blur      描边要硬
transparent background   方便后期合成
```

### 生图后必做两步

1. **检查是否真的对齐像素网格。** 很多 AI 出的"像素风"其实是伪像素——放大看边缘有半透明过渡。有过渡就重生成或手动降采样。
2. **统一色板。** AI 每次出的颜色都会飘。用取色器把素材颜色替换成 `配色方案.md` 里的标准色值。

### 生视频的使用边界

只在这两种情况用：

- 需要真实画面做对比（比如"这是现实中的机房"）
- 复杂的 3D 运镜，手做成本过高

用了 AI 生视频，必须做**风格统一处理**：降色阶到主色板、加像素化滤镜、匹配帧率到 25fps。直接插一段写实 AI 视频进像素风片子，风格就散了。

## 六、配音

### 语气：照何同学

参考特征：

- 平实，不亢奋。不要念稿式的抑扬顿挫，也不要电商叫卖式的激动
- 讲到关键处**放慢**，不是加大音量
- 句子短。一句话讲一件事，不套从句
- 允许留白。该停就停，不用把每一秒都填满声音

### 稿子怎么写

| 要求 | 说明 |
|---|---|
| 语速 | 每分钟 240–280 字。90 秒片子的旁白稿控制在 **340–420 字** |
| 句长 | 单句不超过 25 字 |
| 术语 | 第一次出现必须解释，不许裸用 |
| 口语化 | 「所以」不写「因此」，「就是说」不写「亦即」 |
| 数字 | 写成口播读法（「一百三十」不是「130」） |

### 技术参数

| 项 | 值 |
|---|---|
| 采样率 | 48kHz，16bit 以上 |
| 声道 | 单声道录制，成片时置中 |
| 人声电平 | 峰值 −3dB，响度 −16 LUFS |
| 底噪 | 必须降噪，环境底噪低于 −50dB |
| 格式 | wav（工程内），成片混音后再压 |

### AI 配音能不能用

能用，但两条：

1. **必须听全遍**。AI 配音最常错的是多音字和断句（「重（chóng）新」读成「重（zhòng）新」、「的」当停顿点）。逐句听，错了就改字或加标点强制断句。
2. **不许留 AI 腔**。句末音调平直上扬、每句节奏完全一致，这是 AI 腔的两个特征。手动调整句间停顿长度，破掉机械感。

## 七、剪辑与配乐

### 配乐：照何同学的路子

| 段 | BGM 状态 |
|---|---|
| 钩子（0–8s） | 无 BGM 或极轻的氛围音，让问题落进耳朵 |
| 引入动画（8–20s） | BGM 进入，随标题落定给一个节奏点 |
| 核心演绎（20–65s） | 持续，**音量压到人声之下 12–15dB** |
| 收束（65–82s） | 情绪抬起，但不要突然变大 |
| 片尾（82–90s） | 收尾要收干净，最后 2 秒静场 |

选曲三条：

1. **器乐，不要人声。** 有人声的 BGM 会和旁白抢注意力。
2. **克制，不煽情。** 何同学的配乐特点是垫底不抢戏，情绪由内容给，不由音乐给。
3. **必须是可商用曲库。** 爱给网、Artlist、Epidemic Sound，或 B站创作中心的授权音乐库。用网易云的歌是侵权。

### 音效

像素风片子的音效要跟着动作走：

| 动作 | 音效 |
|---|---|
| 元素入场 | 短促的电子音（8-bit blip） |
| 落定 / 强调 | 一声闷响或"咔"声 |
| 像素消散 | 沙沙的碎裂声 |
| 转场 | 一个 whoosh |

音效电平比 BGM 高 3–6dB，比人声低 6dB。**音效必须精确对齐动作帧**，差两帧就会觉得"不对劲"。

### 剪辑节奏参数

| 项 | 值 |
|---|---|
| 平均镜头时长 | 2.5–4 秒 |
| 最短镜头 | 不短于 1 秒（短于 1 秒来不及理解） |
| 最长镜头 | 不长于 6 秒（除非画面一直在动） |
| 转场 | 硬切为主。像素消散作为特殊转场，全片不超过 3 次 |
| 禁用 | 交叉叠化、旋转、翻页、任何 Pr 预设花活 |

**硬切是默认。** 每加一个转场都要能说出理由。

### 字幕

| 项 | 要求 |
|---|---|
| 位置 | 画面底部，安全区内（距底边 ≥ 8% 画面高度） |
| 单行字数 | 不超过 18 字，超了断成两行 |
| 与旁白 | 逐字对应，不许简写或改写 |
| 错别字 | 交付前必须通读一遍 |

## 八、制作流程（八步，不许跳步）

```
1. 定概念        确认这个概念能在 45 秒的演绎里讲透。讲不透就拆
2. 写文本脚本    旁白稿 340–420 字，按五段结构分好
3. 写动效脚本    9 列填满，特别是「元素入场」和「缓动曲线」
4. 出素材        AI 生图 → 检查像素对齐 → 统一色板
5. 排动画        按动效脚本的时间码和缓动曲线做，一次只动一个东西
6. 录/生配音     听全遍，改多音字和断句
7. 混音配乐      人声 −16 LUFS，BGM 压 12–15dB，音效对齐动作帧
8. 自查交付      过第九节的清单
```

第 3 步之后建议停一下，把动效脚本给人看一遍。**脚本阶段改一行，成片阶段要改半天。**

## 九、交付前逐项打勾

### 结构
- [ ] 总时长在 75–110 秒之间
- [ ] 五段齐全，各段时长符合占比
- [ ] 钩子是真问题，不是「今天我们来讲」
- [ ] 引入动画有明确的标题落定动作
- [ ] 核心演绎拆成 3–5 个小步骤
- [ ] 收束有「一句话定义」+「一个类比」，顺序没颠倒
- [ ] 片尾最后 2 秒是静场

### 动效脚本
- [ ] 9 列全部填满
- [ ] 「元素入场」只用了那五种
- [ ] 「缓动曲线」每一镜都标了
- [ ] 时间码连续，无空档无重叠
- [ ] 成片和脚本的时间码对得上

### 美术
- [ ] 1920×1080，25fps
- [ ] 像素网格基准全片统一（4px 或 8px）
- [ ] **缩放用最邻近，画面没有发虚的像素边缘**
- [ ] 主色板 5–7 色，取自 `配色方案.md`
- [ ] 字体不超过 2 种，**授权已确认**
- [ ] AI 生成素材已检查伪像素、已统一色板
- [ ] AI 生视频（如有）已做像素风后处理

### 动画
- [ ] 任一时刻只有一个主要元素在动
- [ ] 每个动作后有 0.3–0.5 秒停顿
- [ ] 没有不服务于理解的炫技动效

### 声音
- [ ] 旁白 340–420 字，单句不超 25 字
- [ ] 术语第一次出现有解释
- [ ] 人声 −16 LUFS，峰值 −3dB
- [ ] 已降噪，无明显底噪
- [ ] AI 配音已逐句听过，多音字和断句正确
- [ ] 没有 AI 腔（句末平直上扬、节奏机械）
- [ ] BGM 是器乐、无人声、**可商用**
- [ ] BGM 压在人声下 12–15dB
- [ ] 音效精确对齐动作帧
- [ ] 片尾 BGM 收干净，没卡在音乐中间
